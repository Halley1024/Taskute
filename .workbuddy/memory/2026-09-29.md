### 已确认的四个关键决策（经 AskUserQuestion 与用户确认）

1. **数据模型三层**：任务 → 阶段 → 步骤。阶段是独立实体，承载"分阶段标记完成"。
2. **Rust 侧 sqlx + `sqlx::migrate!()`**，不用 ORM。与既有 civil-career-exam 选 sqlc 的取向一致。
3. **平台范围仅 desktop**，`android/` 占位；但 `services/` 层禁止引用 tauri 类型，为未来抽 `taskute-core` crate 留门。
4. **图渲染分工**：DAG + 脉络图用 React Flow；完成日历 + 优先级矩阵用 ECharts。

### 设计过程中自我修正的几处

- **D-08 软删范围**：初稿写"task/stage/step 全带 deleted_at"，写到 step 表时发现软删步骤会让依赖边残留 → DAG 出现"看不见但在约束图中"的幽灵节点。**改为 step 硬删**，`deleted_at` 字段保留但恒为 NULL（未来回收站扩展位）。已回改 00/02/04/DECISION_LOG 四处。
- **解锁判定**：因 step 改硬删，`P.deleted_at IS NOT NULL` 这条判据删除——被删步骤的边已随 CASCADE 消失，不需要特判。
- **阶段完成度的连带语义**：初稿"勾选阶段 → 该阶段步骤解锁判定视为通过"表述有歧义，会被读成矛盾。改为明确的"数据层不改写步骤 is_done，仅查询层排除出今日推荐"。

### 几个值得记住的设计取舍

- **`sqlx::query!` 编译期宏不用**：需要 `DATABASE_URL` 指向已迁移的库，首次 clone / CI 会卡人。改用 `query_as` + 手写 `FromRow`，靠集成测试兜类型。
- **`create_step` 依赖语义三分支**：`None`（用户没说→默认推导）/ `Some(vec)`（手动指定）/ `no_dependency=true`（显式无依赖）。必须区分 `None` 与 `Some([])`，这是 `Option<Vec<_>>` 的存在理由。
- **今日排序权重 45/35/20**（urgency/importance/quick_win），常量放 `schedule.rs` 顶部便于调参。逾期任务 urgency 封顶 1.0 不再上升——刻意设计。
- **优先级矩阵 X 轴用 urgency 而非剩余天数**：线性轴无法区分"刚逾期"与"逾期 30 天"。
- **`order_index` 间隔 10**，插入取中点，耗尽（同位置连插 4 次）触发全组重排。
- **NSIS 必须设 `deleteAppDataOnUninstall: false`**，否则卸载/重装丢全部用户数据。
